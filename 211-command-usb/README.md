# Практика 2.1 — Исполнение ВПО в микроконтроллере

Сквозной проект `211-command-usb` для Raspberry Pi Pico / RP2040.
Код заданий 2.1.1–2.1.6 собран в итоговом варианте проекта.

## Команды

| Команда | Действие |
| --- | --- |
| `enable`, `disable` | Включить или выключить светодиод GPIO 25 |
| `info` | Паспорт, реальный серийный номер, CHIP_ID и версия Pico SDK |
| `version` | Версия прошивки и уровень журнала |
| `ping` | Ответ `pong` |
| `mem_info` | Границы памяти и секций из символов линкера, размеры и итоги |
| `fw_info` | Адреса функций, таблицы, констант, переменных, стека и кучи |
| `dev_info` | Размеры, адреса и смещения полей `device_card` |
| `boot_info` | Первые слова таблицы векторов и состояние GPIO_IN |

Команда выполняется после Enter (`CR`, `LF` или `CRLF`). Ввод отображается,
Backspace удаляет последний символ. Строка длиннее 31 символа отвергается целиком.
Кнопка GPIO 15 с подтяжкой к питанию переключает светодиод при нажатии;
контакт кнопки соединяется с GND. Антидребезг 20 мс не задерживает приём USB.

## Сборка в WSL / Linux

```bash
export PICO_SDK_PATH="$HOME/Repositories/pico/pico-sdk"
cmake -S . -B build -DPICO_BOARD=pico
cmake --build build -j4
```

Полученный файл: `build/211_command_usb.uf2`.
Используются Pico SDK 2.3.0 и ARM GCC; SDK и результаты сборки не включены в Git.

## Что осталось проверить на плате

### Расчётные логи без Pico

В `offline/expected-2-1-1.log` — `offline/expected-2-1-6.log` записаны ожидаемые
ответы для шести сценариев. Их создаёт `python3 offline/generate_logs.py`
после сборки. Это расчётная модель, а не исполнение прошивки или обмен по USB.
Адреса секций, таблица команд, начальные значения структуры и первые слова
таблицы векторов прочитаны из настоящего ELF/BIN. Значения счётчиков и GPIO
смоделированы. Серийный номер, CHIP_ID, время обмена и адреса блока кучи и
локальной переменной без платы не определялись. Эти файлы не заменяют
аппаратные `device-2-1-K.log`, которые требует проверка курса.

### Реальный прогон

При подготовке работы платы не было. Файлы `device-2-1-K.log` пока отсутствуют:
ответы устройства и серийный номер не имитировались. Полная сдача курса требует
реального прогона на Pico; проверки GitHub будут сообщать об отсутствии этих логов.

1. Подключить Pico с зажатой BOOTSEL и скопировать UF2 на диск `RPI-RP2`.
2. После перезапуска закрыть терминал, который занимает COM-порт.
3. Установить `pyserial` в Python на системе, где виден USB-порт платы.
4. Из этой папки запустить все шесть исходных скриптов из книги:

```bash
python check-2-1-1.py
python check-2-1-2.py
python check-2-1-3.py
python check-2-1-4.py
python check-2-1-5.py
python check-2-1-6.py
```

5. Проверить ответы в логах и добавить шесть полученных файлов в Git.

Дополнительно: сравнить адреса `mem_info` с `.elf.map`, проверить рост переменных
при трёх вызовах `fw_info`, их сброс после перезапуска, а также изменение `led bit`
и `gpio_get` после `enable` и `disable`. `device_card` должен занимать 20 байт:
поля 18 байт, хвостовое заполнение 2 байта. Исходный порядок
`revision/version/name` занимает 24 байта из-за выравнивания; итоговый порядок
`version/name/revision` экономит 4 байта. `commands` остаётся константной таблицей
во флеш-памяти; блок `malloc` освобождается после каждого вызова `fw_info`.
